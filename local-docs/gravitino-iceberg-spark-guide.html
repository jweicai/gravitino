Gravitino Iceberg REST Catalog 部署指南

适用于阿里云 EMR 集群，Spark/Flink 通过 Gravitino Iceberg REST Server 读写 Iceberg 表，元数据存 PostgreSQL，数据存 OSS，无需 Hive Metastore。

架构

Spark / Flink
      │
      │ Iceberg REST API
      ▼
Gravitino Iceberg REST Server (:8090)
      │
      │ JDBC
      ▼
PostgreSQL (Iceberg 元数据)
      │
      ▼
Alibaba Cloud OSS (Iceberg 数据文件)

前置条件

  • 阿里云 EMR 集群（已安装 Spark 3.3.x、JindoSDK）

  • PostgreSQL 数据库（RDS 或自建）

  • Gravitino 1.2.0 安装包

  • Iceberg Spark Runtime JAR（版本需匹配 Spark，如 iceberg-spark-runtime-3.3_2.12-1.4.3.jar）

第一步：安装 Gravitino

# 下载并解压（假设安装到 /opt/gravitino/）
cd /opt/gravitino
tar xzf gravitino-1.2.0-bin.tar.gz

第二步：配置 Iceberg REST Server

关键： Gravitino 有两个配置文件都包含 gravitino.iceberg-rest.* 配置，两个都必须改，否则独立配置文件会覆盖主配置。

2.1 修改主配置 conf/gravitino.conf

cd /opt/gravitino/gravitino-1.2.0-bin

找到以下配置项并修改：

gravitino.iceberg-rest.httpPort = 8090
gravitino.iceberg-rest.catalog-backend = jdbc
gravitino.iceberg-rest.uri = jdbc:postgresql://<PG_HOST>:<PG_PORT>/<DB_NAME>
gravitino.iceberg-rest.jdbc-driver = org.postgresql.Driver
gravitino.iceberg-rest.jdbc-user = <DB_USER>
gravitino.iceberg-rest.jdbc-password = <DB_PASSWORD>
gravitino.iceberg-rest.jdbc-initialize = true
gravitino.iceberg-rest.warehouse = oss://<BUCKET>/<PREFIX>/

2.2 修改独立配置 conf/gravitino-iceberg-rest-server.conf

这个文件优先级更高，不改这里等于白改。 找到以下配置项并修改：

gravitino.iceberg-rest.httpPort = 8090
gravitino.iceberg-rest.catalog-backend = jdbc
gravitino.iceberg-rest.uri = jdbc:postgresql://<PG_HOST>:<PG_PORT>/<DB_NAME>
gravitino.iceberg-rest.jdbc-driver = org.postgresql.Driver
gravitino.iceberg-rest.jdbc-user = <DB_USER>
gravitino.iceberg-rest.jdbc-password = <DB_PASSWORD>
gravitino.iceberg-rest.jdbc-initialize = true
gravitino.iceberg-rest.warehouse = oss://<BUCKET>/<PREFIX>/

2.3 一键替换脚本

将以下变量替换为实际值后直接执行：

# ============ 修改这里 ============
PG_HOST="pgm-xxx.pg.rds.aliyuncs.com"
PG_PORT="1921"
PG_DB="gravitino_iceberg_catalog"
PG_USER="gravitino"
PG_PASS="your-password"
OSS_WAREHOUSE="oss://your-bucket/warehouse/"
# ==================================


GRAVITINO_HOME=/opt/gravitino/gravitino-1.2.0-bin


for CONF_FILE in \
  "$GRAVITINO_HOME/conf/gravitino.conf" \
  "$GRAVITINO_HOME/conf/gravitino-iceberg-rest-server.conf"; do


  # backup
  cp "$CONF_FILE" "${CONF_FILE}.bak"


  # catalog-backend: memory -> jdbc
  sed -i 's|^\(gravitino.iceberg-rest.catalog-backend\s*=\s*\).*|\1jdbc|' "$CONF_FILE"


  # warehouse: /tmp -> oss
  sed -i "s|^\(gravitino.iceberg-rest.warehouse\s*=\s*\).*|\1${OSS_WAREHOUSE}|" "$CONF_FILE"


  # 追加 JDBC 配置（如果不存在）
  grep -q "gravitino.iceberg-rest.jdbc-driver" "$CONF_FILE" || cat >> "$CONF_FILE" << EOF


# JDBC catalog backend config (auto-added)
gravitino.iceberg-rest.uri = jdbc:postgresql://${PG_HOST}:${PG_PORT}/${PG_DB}
gravitino.iceberg-rest.jdbc-driver = org.postgresql.Driver
gravitino.iceberg-rest.jdbc-user = ${PG_USER}
gravitino.iceberg-rest.jdbc-password = ${PG_PASS}
gravitino.iceberg-rest.jdbc-initialize = true
EOF


done


echo "Done. Verify:"
grep "gravitino.iceberg-rest" "$GRAVITINO_HOME/conf/gravitino-iceberg-rest-server.conf" | grep -v "^#"

第三步：添加 OSS（JindoFS）依赖

阿里云 EMR 使用 JindoFS 访问 OSS，Gravitino REST Server 默认不包含这些依赖，必须手动添加：

GRAVITINO_HOME=/opt/gravitino/gravitino-1.2.0-bin
REST_LIBS=$GRAVITINO_HOME/iceberg-rest-server/libs
REST_CONF=$GRAVITINO_HOME/iceberg-rest-server/conf


# 1. 复制 JindoSDK JAR
cp /opt/apps/JINDOSDK/jindosdk-current/lib/jindo-core-*.jar $REST_LIBS/
cp /opt/apps/JINDOSDK/jindosdk-current/lib/jindo-sdk-*.jar $REST_LIBS/


# 2. 复制 Hadoop core-site.xml（含 JindoFS/OSS 认证配置）
cp /etc/emr/hadoop-conf/core-site.xml $REST_CONF/core-site.xml


# 验证
echo "=== JindoSDK JARs ==="
ls $REST_LIBS/jindo-*.jar
echo "=== core-site.xml ==="
grep -c "jindo\|oss" $REST_CONF/core-site.xml

第四步：启动 Gravitino

Gravitino 需以 hadoop 用户运行（确保 Kerberos/OSS 权限正确）：

GRAVITINO_HOME=/opt/gravitino/gravitino-1.2.0-bin


# 确保无残留进程
ps aux | grep GravitinoServer | grep -v grep | awk '{print $2}' | xargs kill -9 2>/dev/null
rm -f $GRAVITINO_HOME/pid/gravitino-server.pid 2>/dev/null


# 以 hadoop 用户启动
su - hadoop -c "cd $GRAVITINO_HOME && ./bin/gravitino.sh start"


# 等待启动完成
sleep 5


# 验证
echo "=== 进程 ==="
ps aux | grep GravitinoServer | grep -v grep | awk '{print $1, $2, "OK"}'


echo "=== 管理端 (8091) ==="
curl -s http://localhost:8091/api/version


echo "=== Iceberg REST (8090) ==="
curl -s http://localhost:8090/iceberg/v1/config | head -c 50


echo "=== 确认 JDBC backend ==="
grep "Load catalog backend" $GRAVITINO_HOME/logs/gravitino-server.log | tail -1

预期输出应包含： Load catalog backend of JDBC

第六步：端到端验证

6.1 创建测试 SQL

xxxxxxxxxx
cat > /tmp/gravitino_verify.sql << 'EOF'
-- 建库

-- 建表
CREATE TABLE IF NOT EXISTS gvt_iceberg.test_db.test_table (
  id BIGINT,
  name STRING,
  created_at TIMESTAMP
) USING iceberg;


-- 写入
INSERT INTO gvt_iceberg.test_db.test_table VALUES
  (1, 'hello', TIMESTAMP '2026-03-25 10:00:00'),
  (2, 'world', TIMESTAMP '2026-03-25 11:00:00'),

-- 确认数据在 OSS 上（LOCATION 必须是 oss://）

踩坑记录

坑 1：Gravitino Spark Connector 不支持 JDBC Backend

现象：

xxxxxxxxxx
java.lang.IllegalStateException: Unknown catalog type: jdbc
  at org.apache.gravitino.spark.connector.catalog.BaseCatalog.initialize

原因： Gravitino Spark Connector 1.2.0 的 BaseCatalog.initialize() 中的 switch-case 不包含 jdbc 类型，尽管 IcebergCatalogBackend 枚举中有 JDBC。这是 connector 的 bug。

解决方案： 不使用 Gravitino Spark Connector（gravitino-spark-connector-runtime-*.jar），改用 Iceberg 原生 REST Catalog 直接对接 Gravitino Iceberg REST Server。配置从：

xxxxxxxxxx
# 错误方式（使用 Gravitino Connector）
spark.plugins = org.apache.gravitino.spark.connector.plugin.GravitinoSparkPlugin
spark.sql.catalog.xxx = org.apache.gravitino.spark.connector.iceberg.GravitinoIcebergCatalog

改为：

xxxxxxxxxx
# 正确方式（使用 Iceberg 原生 REST Catalog）
spark.sql.catalog.xxx = org.apache.iceberg.spark.SparkCatalog
spark.sql.catalog.xxx.type = rest
spark.sql.catalog.xxx.uri = http://localhost:8090/iceberg/

功能完全等价，兼容性更好。

坑 2：两个配置文件，改一个不够

现象： 修改了 gravitino.conf 中的 catalog-backend = jdbc，重启后日志仍显示 committed to table memory.xxx，数据写到 /tmp/。

原因： Gravitino 的 Iceberg REST Server 有独立配置文件 conf/gravitino-iceberg-rest-server.conf，优先级高于 gravitino.conf。只改 gravitino.conf 无效。

解决方案： 两个文件都必须改。特别是 gravitino-iceberg-rest-server.conf 中的：

  • gravitino.iceberg-rest.catalog-backend

  • gravitino.iceberg-rest.warehouse

  • JDBC 连接参数

坑 3：OSS 写入失败 — 缺少 JindoFS 依赖

现象：

xxxxxxxxxx
Server error: RuntimeException: java.lang.ClassNotFoundException:
  Class com.aliyun.jindodata.oss.JindoOssFileSystem not found

原因： 阿里云 EMR 使用 JindoFS（不是标准 hadoop-aliyun）作为 OSS 文件系统实现。Gravitino REST Server 的 classpath 默认不包含 JindoFS JAR，也没有 Hadoop 的 core-site.xml（含 OSS 认证信息）。

解决方案：

xxxxxxxxxx
# 复制 JindoSDK
cp /opt/apps/JINDOSDK/jindosdk-current/lib/jindo-core-*.jar  iceberg-rest-server/libs/
cp /opt/apps/JINDOSDK/jindosdk-current/lib/jindo-sdk-*.jar   iceberg-rest-server/libs/


# 复制 Hadoop 配置（含 OSS 认证）
cp /etc/emr/hadoop-conf/core-site.xml  iceberg-rest-server/conf/

坑 4：EMR 全局 Catalog 名冲突

现象：

xxxxxxxxxx
java.lang.IllegalArgumentException: Cannot create catalog iceberg,
  both type and catalog-impl are set: type=rest,
  catalog-impl=org.apache.iceberg.aliyun.dlf.hive.DlfCatalog

原因： EMR 在 spark-defaults.conf 中全局配置了 spark.sql.catalog.iceberg 使用 DlfCatalog。当用户再设置 spark.sql.catalog.iceberg.type=rest 时，Iceberg 发现 type 和 catalog-impl 同时存在，冲突报错。

解决方案： Spark Catalog 名不要用 iceberg，改用其他名称如 gvt_iceberg：

xxxxxxxxxx
spark.sql.catalog.gvt_iceberg = org.apache.iceberg.spark.SparkCatalog
spark.sql.catalog.gvt_iceberg.type = rest

坑 5：Gravitino 进程 stop 不掉

现象： 执行 ./bin/gravitino.sh stop 提示 "not running"，但 ps aux 仍能看到 GravitinoServer 进程。

原因： Gravitino 以 hadoop 用户启动，root 用户执行 stop 脚本时读取的 PID 文件路径不同，找不到进程。

解决方案：

xxxxxxxxxx
# 强制杀进程
ps aux | grep GravitinoServer | grep -v grep | awk '{print $2}' | xargs kill -9
rm -f /opt/gravitino/gravitino-1.2.0-bin/pid/gravitino-server.pid


# 以 hadoop 用户重启
su - hadoop -c "cd /opt/gravitino/gravitino-1.2.0-bin && ./bin/gravitino.sh start"

坑 6：spark-sql -e 多行 SQL 粘贴截断

现象： 在终端粘贴带 -e "多行SQL" 的命令时，SQL 被截断，只剩 -e "。

原因： 终端对多行字符串的粘贴处理不一致。

解决方案： 将 SQL 写入文件，用 -f 执行：

xxxxxxxxxx
cat > /tmp/test.sql << 'EOF'
SELECT 1;
EOF
spark-sql ... -f /tmp/test.sql
